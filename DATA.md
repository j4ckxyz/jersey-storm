# Data contract

This file describes every piece of data the frontend reads. Use it to change the UI (`index.html`, `app.js`, `style.css`) without breaking the site.

## Who owns what

| File | Owner | Notes |
|---|---|---|
| `summary.json` | **Automated refresh** (rewritten every few hours until Fri 23 Oct 2026 night) | Don't hand-edit during the storm; your edits will be overwritten. |
| `x-posts.json` | **Automated refresh** (regenerated by `tools/build_x_posts.py`) | Same. |
| `events.json` | **Automated refresh** (written by the assistant's scheduled runs) | Grouped storm events. The UI only reads it. See [Grouped storm events](#grouped-storm-events-eventsjson-static-served-at-eventsjson). |
| `index.html`, `app.js`, `style.css` | **You (Jack)** | Change these freely, but keep reading the data below as documented. |
| `api/*.js`, `lib/*.js` | Serverless functions | They produce `/api/feed` and `/api/weather`. Leave them alone unless you mean to change the contract. |
| `tools/*.py`, `UPDATE.md` | Refresh tooling | The automated refresh uses them. `tools/prepare_deploy.py` validates both JSON files before every deploy. |

## Rules

1. **Keep field names and types.** The refresh writes exactly the fields below. Don't rename them or change their types.
2. **New fields must be optional.** Add them only as optional fields, and existing consumers must keep working without them.
3. **The frontend must tolerate missing optional fields** (and empty arrays or strings). Treat anything marked *optional* as possibly absent.
4. **Timestamps are ISO 8601 strings**, for example `2026-10-22T06:08:49.000Z` or `2026-10-22T07:45:00+01:00`. Parse them with `new Date()`. Show them to people in `Europe/Jersey` time.
5. **All URLs are absolute `http(s)://` URLs.** The UI passes every URL through `safeUrl()` and escapes all text with `esc()`. Never put raw HTML from data into the page.

## `summary.json` (static, served at `/summary.json`)

This file feeds the "What's happening" box. It is rewritten by the refresh.

| Field | Type | Req. | Meaning |
|---|---|---|---|
| `updatedAt` | string (ISO 8601) | required | When the summary was written. The UI shows "Updated HH:MM, Weekday" and adds "may be out of date" after 6 h. |
| `headline` | string (mini-markdown) | required | Lead paragraph. If it is missing or empty, the box is hidden. |
| `sections` | array of `{ title: string, points: string[] }` | required (may be empty) | The first section is always shown. The rest sit inside "Show full summary". Each `points` entry is mini-markdown. |
| `posts` | string[] | optional | **URLs** of any feed item (tweets, Bluesky posts, BBC/JEP/gov.je articles, etc.) shown under "Key updates", sorted newest first regardless of type. |
| `note` | string | optional | A comment for editors. The UI never shows it. |

**Mini-markdown (the only syntax supported, in `headline` and `points`):**
- `**bold**` becomes `<strong>`.
- `[label](https://url)` becomes a link that opens in a new tab. Only `http(s)` URLs work, with no spaces or `)` in the URL.
- Everything else is HTML-escaped, so raw HTML shows up as plain text. Every factual claim carries an inline link.

**How `posts` are resolved:** each URL is matched *exactly* against `url` in the post pool. The pool is all of `x-posts.json` plus every item from `/api/feed` (posts and articles alike). Posts render as post cards, everything else as normal feed items. Unmatched URLs are skipped silently. X post URLs must therefore also appear in `x-posts.json`, in the form `https://x.com/<handle>/status/<id>`. Bluesky URLs use the form `https://bsky.app/profile/<handle>/post/<rkey>`.

```json
{
  "updatedAt": "2026-10-22T07:45:00+01:00",
  "note": "Edit this file to update the summary box.",
  "headline": "Storm Austen peaks around 7am Friday with **gusts of 70–80 mph** ([gov.je](https://www.gov.je/News/2026/Pages/StormAustenUpdates.aspx)).",
  "sections": [
    { "title": "So far", "points": ["**All Government of Jersey schools are closed on Friday** ([gov.je](https://www.gov.je/))."] }
  ],
  "posts": ["https://x.com/GovJersey/status/2112956056640934300"]
}
```

## `x-posts.json` (static, served at `/x-posts.json`)

This file is regenerated by the refresh. The site has no X API key, so X posts come only from here.

Top level: `{ "generatedAt": string (ISO 8601), "posts": Post[] }`.

| Post field | Type | Req. | Meaning |
|---|---|---|---|
| `id` | string | required | Tweet id (numeric string). |
| `handle` | string | required | Screen name without `@`, e.g. `Jersey_Met`. |
| `text` | string | required | Plain text. It may contain `\n`, so render it with `white-space: pre-wrap`. |
| `time` | string (ISO 8601 UTC, e.g. `2026-10-22T06:08:49.000Z`) | required | Post time. |
| `url` | string | required | `https://x.com/<handle>/status/<id>`. This is the key for dedupe and for `summary.posts`. |
| `source` | string | always `"X"` | |
| `platform` | string | always `"x"` | |
| `author` | string | optional (may be `""`) | Display name. The UI falls back to `handle`. |
| `avatar` | string (URL) | optional (may be `""`) | Profile image. X avatars are served same-origin through `/api/x-avatar?u=<avatar>` (so content blockers that block pbs.twimg.com don't hide them). If that fails, the UI tries `/api/x-avatar?id=<id>` (tweet syndication lookup), then the URL directly, then an initial letter. |
| `media` | Media[] | optional (may be `[]`) | Up to 4 items. |

`prepare_deploy.py` checks that `id`, `handle`, `text`, `time` and `url` are present.

**Media item** (the same shape for X and Bluesky):

| Field | Type | Req. | Meaning |
|---|---|---|---|
| `type` | `"photo"` \| `"video"` \| `"animated_gif"` \| `"link"` | required | `video` and `animated_gif` get a ▶ overlay, using only the thumbnail. `link` is a link-preview card. |
| `url` | string | required | Image URL (full size for photos, the thumbnail for video and link). |
| `thumb` | string | optional | Thumbnail. The UI prefers it over `url`. |
| `alt` | string | optional | Alt text. |
| `link` | string | `link` only, optional | Target URL of the preview. |
| `title` | string | `link` only, optional | Preview title. |

A single `link` item renders as a preview card. Otherwise, `link` items are dropped and up to 4 images render in a grid.

```json
{
  "generatedAt": "2026-10-22T06:34:16Z",
  "posts": [{
    "id": "2113150564121083909", "source": "X", "platform": "x",
    "author": "Jersey Met", "handle": "Jersey_Met",
    "avatar": "https://pbs.twimg.com/profile_images/1859262056265924609/JIBulToH_bigger.jpg",
    "text": "Jersey today: Bright or sunny spells and showers…",
    "media": [{ "type": "photo", "url": "https://pbs.twimg.com/media/HVLn_UVWIAAbfVJ.jpg", "thumb": "https://pbs.twimg.com/media/HVLn_UVWIAAbfVJ.jpg", "alt": "" }],
    "time": "2026-10-22T06:08:49.000Z",
    "url": "https://x.com/Jersey_Met/status/2113150564121083909"
  }]
```

## Grouped storm events: `events.json` (static, served at `/events.json`)

This file replaces the long list of posts with **events**. Each event groups the posts and articles (X, Bluesky, BBC, JEP, gov.je, Facebook, other sites) from around the same time that are about the same thing. It has a short summary, a longer description for a dropdown, and the cited sources so readers can open the original posts.

- **The assistant's scheduled refresh runs generate it.** They rewrite the whole file each run. Don't hand-edit it during the storm.
- **The UI only reads it.** It never writes to it. Fetch it with a fallback, e.g. `fetch('/events.json', {cache: 'no-store'}).then(r => r.ok ? r.json() : null).catch(() => null)`. If it is missing or `events` is empty, fall back to the existing feed.
- `tools/prepare_deploy.py` deploys it alongside the other static files.

### Top level

```
{ "version": 1, "updated": string, "timezone": "Europe/Jersey", "events": Event[] }
```

| Field | Type | Req. | Meaning |
|---|---|---|---|
| `version` | number | required | Shape version, currently `1`. It only changes if the shape changes incompatibly. |
| `updated` | string (ISO 8601 with offset, e.g. `2026-10-22T15:55:00+01:00`) | required | When the file was generated. Show it as "Updated 3:55pm" and flag it as possibly out of date after 6 h, like `summary.updatedAt`. |
| `timezone` | string | required | Always `"Europe/Jersey"`. Use it for every displayed time. |
| `events` | Event[] | required (may be `[]`) | Sorted **newest first** by `end` (latest activity), then `start`. Render them in the given order and don't re-sort. |

### Event

| Field | Type | Req. | Meaning |
|---|---|---|---|
| `id` | string | required | A stable slug, e.g. `2026-10-22-red-warning-issued`. It stays the same across runs while the event is updated, so use it as the DOM key and for "open/closed" or "seen" state in `localStorage`. |
| `start` | string (ISO 8601 with offset) | required | Time of the earliest source in the event. |
| `end` | string (ISO 8601 with offset) | required | Time of the latest source. Equal to `start` when there is a single source time. |
| `title` | string | required | Short headline (plain text, about ≤ 80 chars). |
| `summary` | string | required | One or two plain-text sentences, always visible. |
| `details` | string | required | A few sentences shown inside the dropdown. Claims carry inline refs `[1]`, `[2]`… which are **1-based** indexes into `sources`. Not every source has to be referenced, because some only corroborate. |
| `category` | enum | required | `warning` \| `weather` \| `travel` \| `power` \| `closures` \| `damage` \| `emergency` \| `advice` \| `other`. Unknown values should be treated as `other`. |
| `severity` | enum | required | `info` \| `notable` \| `major`. Use it for emphasis, e.g. a coloured edge for `major`. Unknown values should be treated as `info`. |
| `area` | enum | required | `jersey` \| `guernsey` \| `both`. Jersey comes first. Guernsey-only events are included only when they matter to Jersey readers (major incidents, big power cuts, flights or ferries). |
| `sources` | Source[] | required (≥ 1) | Ordered as cited by `[n]`, usually oldest first. |

### Source

| Field | Type | Req. | Meaning |
|---|---|---|---|
| `type` | enum | required | `x` \| `bluesky` \| `bbc` \| `jep` \| `gov` \| `facebook` \| `web` \| `other`. Use it for the icon/label. Unknown values should be treated as `other`. |
| `publisher` | string | required | Who published it, e.g. `"BBC Jersey"`, `"Government of Jersey"`, `"Jersey Met"`, `"today.je (relaying Jersey Electricity Facebook)"`. |
| `author` | string | required (may be `""`) | The handle **without `@`** for X and Bluesky (e.g. `GovJersey`, `today.je`), or a byline for articles. It may be `""`. |
| `title` | string | required | Article headline, or a short excerpt of the post. Plain text. |
| `url` | string | required | Absolute `https://` link to the actual post or article. X URLs use the form `https://x.com/<handle>/status/<id>`, and Bluesky URLs use `https://bsky.app/profile/<handle>/post/<rkey>`. A live-blog page (e.g. Channel 103) may appear more than once in an event, with different `time`s for different entries. |
| `time` | string (ISO 8601 with offset) | required | When this source published the cited item. For pages with no timestamp, it is the time the page was first shared (e.g. by a dated post linking to it). Times are never invented. |

All text fields are **plain text**. There is no markdown or HTML, so escape them with `esc()` and pass URLs through `safeUrl()`. To link refs, replace each `[n]` in `details` (regex `/\[(\d+)\]/g`) with a small link or anchor to `sources[n-1]`. If `n` is out of range, leave it as text.

### Display guidance

- **Show all times in `Europe/Jersey`**, e.g. with `Intl.DateTimeFormat('en-GB', { timeZone: 'Europe/Jersey', … })`. Never use the viewer's local zone. Jersey moves from BST (+01:00) to GMT (+00:00) on 25 Oct 2026, and `Intl` handles that.
- **Today's items** (same Jersey calendar date as now) show just the time, in lowercase 12-hour format: `3:10pm`, `11:05am`, and `12:00pm` for noon.
- **Older items** show weekday, day, month and time: `Thu 22 Oct, 3:10pm`. Add the year only if it is not the current year.
- **Ranges:** when `start` and `end` differ, show `start–end`. If both fall on the same day, give the date once: `10:19–10:32am` or `11:30am–2:18pm` today, and `Wed 21 Oct, 6:15–8:00pm` on an older day. If they span days, give both: `Tue 20 Oct, 4:05pm – Wed 21 Oct, 9:37pm`. If they are equal, show the single time.
- **Dropdown:** show `details`, then the sources list. Each source shows its type icon, `publisher`, `@author` (for X and Bluesky), `title`, and **its own time** in the same format, linking to `url` in a new tab (`rel="noopener"`).
- Badges: `category` as a chip, `severity` for emphasis, and `area` as a small "Jersey", "Guernsey" or "Jersey & Guernsey" label.

Example time formatter:

```js
const TZ = 'Europe/Jersey';
const dayKey = d => new Intl.DateTimeFormat('en-CA', { timeZone: TZ, year: 'numeric', month: '2-digit', day: '2-digit' }).format(d);
const clock = d => new Intl.DateTimeFormat('en-US', { timeZone: TZ, hour: 'numeric', minute: '2-digit', hour12: true }) // en-US: en-GB gives "0:00pm" at noon
  .format(d).replace(/\s/g, '').toLowerCase();                        // "3:10pm"
const dateLabel = d => new Intl.DateTimeFormat('en-GB', { timeZone: TZ, weekday: 'short', day: 'numeric', month: 'short' })
  .format(d).replace(',', '');                                         // "Thu 22 Oct"
function fmtTime(iso, now = new Date()) {
  const d = new Date(iso);
  return dayKey(d) === dayKey(now) ? clock(d) : `${dateLabel(d)}, ${clock(d)}`;
}
```

### Stability rules

- Field names and types above are fixed for `version: 1`. Any new fields will be optional, and the UI must ignore fields it doesn't know.
- Event `id`s are stable. An event can gain sources and see its `end`, `summary` and `details` change between runs. An event may also be dropped if it turns out to be wrong or irrelevant.

## `GET /api/feed` (serverless, `lib/feed.js`)

It always returns HTTP 200 JSON. It is cached for 60 s (browser) and 120 s (CDN).

```
{ items: Item[], sources: Source[], generatedAt: string (ISO 8601) }
```

- `items` holds only the last 5 days, deduped by `url`, sorted newest first, with at most 150 entries. Future timestamps are clamped to "now".
- **The API does not group items.** The UI groups them into headings itself: "Today 14:00" per hour, or just the day for `dateOnly` items, in Europe/Jersey time.
- If the whole function fails: `{ "items": [], "sources": [{ "name": "feed", "ok": false, "error": "..." }], "generatedAt": "..." }`.

**Source** (one per fetcher): `{ name: string, ok: boolean, count: number, error?: string }`. `error` is present only when `ok` is false (max 200 characters). The UI lists sources with `ok: false` as "unavailable: …".

**Source ids**, as `sources[].name` → `items[].source`:

| `sources[].name` | `items[].source` | Kind |
|---|---|---|
| `BBC Jersey` | `BBC Jersey` | RSS news |
| `BBC Guernsey` | `BBC Guernsey` | RSS news |
| `gov.je` | `gov.je` | gov.je news page (`dateOnly` usually true) |
| `Jersey Met warnings` | `Jersey Met` | Weather warnings (has `warning`) |
| `Jersey Evening Post` | `Jersey Evening Post` | RSS news |
| `Bailiwick Express` | `Bailiwick Express` | RSS news |
| `The Quarry (Guernsey)` | `The Quarry (Guernsey)` | RSS news |
| `Bluesky` | `Bluesky` | Post (`platform: "bsky"`) |
| *(added by app.js)* `X` | `X` | Post from `x-posts.json` (`platform: "x"`) |
| *(error only)* `feed` | – | The whole function failed |

**News or warning item:**

| Field | Type | Req. | Notes |
|---|---|---|---|
| `source` | string | required | See the table above. |
| `title` | string | required | |
| `text` | string | optional (may be `""`) | Truncated to about 260–280 characters. |
| `url` | string | required | Jersey Met items link to `https://www.gov.je/weather/#<island>-<kind>` (Jersey and Channel Islands) or `.../guernsey-forecast/#…` (Guernsey). |
| `time` | string (ISO 8601) | required | |
| `dateOnly` | boolean | optional | gov.je only. When true, the time is midnight and only the day is meaningful. |
| `warning` | `"yellow"` \| `"amber"` \| `"red"` (lowercase colour) | optional | Jersey Met only. |

**Bluesky item:**

```json
{ "source": "Bluesky", "platform": "bsky", "author": "Jersey Met", "handle": "jerseymet.bsky.social",
  "title": "", "avatar": "https://cdn.bsky.app/…", "text": "Red wind warning…",
  "media": [{ "type": "photo", "url": "https://cdn.bsky.app/…", "thumb": "https://cdn.bsky.app/…", "alt": "" }],
  "url": "https://bsky.app/profile/jerseymet.bsky.social/post/3abc…", "time": "2026-10-22T05:10:00.000Z" }
```

`author` is `""` when the display name is missing or longer than 32 characters. `avatar` may be `""`. Text is collapsed and truncated to 500 characters. Media uses the shape above, with types `photo`, `video` (thumbnail only) and `link`.

**News example:**


## `GET /api/weather` (serverless, `lib/weather.js`)

It always returns HTTP 200 JSON, with the same caching as `/api/feed`. The data comes from Jersey Met.

```
{
  forecast: Forecast | null,          // null if the forecast couldn't be fetched or parsed
  warnings: Warning[],                // Jersey warnings only; [] if none or on error
  warningsChecked: string | null,     // Jersey Met's own "lastChecked" value, passed through unchanged
  sources: { forecast: {ok, error?}, warnings: {ok, error?} },
  generatedAt: string (ISO 8601)
}
```

If the whole function fails: `{ forecast: null, warnings: [], sources: { error: "..." }, generatedAt }`.

**Forecast:** `{ currentTemp: number|null (°C), issued: string (free text such as "06:00 22 October 2026"), days: Day[] }`. Day 0 is today.

**Day:**

| Field | Type |
|---|---|
| `day` | string (e.g. `"Thursday"`) |
| `summary`, `icon`, `windDescription` | string (may be `""`) |
| `max`, `min` | number\|null (°C) |
| `windDir`, `windForce` | string (e.g. `"SW"`, `"F6"`), may be missing |
| `windMph` | number\|null |
| `maxGustMph` | number\|null (highest "gusts … N mph" found in the wind text) |
| `maxRain` | number (max period rain %, 0 if unknown) |
| `sunrise`, `sunset`, `uv` | as Jersey Met supplies them (strings), may be missing |
| `periods` | Period[3]: Morning, Afternoon, Night |

**Period:** `{ name: "Morning"|"Afternoon"|"Night", desc: string, wind: string, dir: string, force: string, mph: number|null, rain: number|null (%), gustMph: number|null }`.

**Warning:** `{ type: string, island: string, kind: "Wind"|"Thunderstorm"|"Tide"|"Snow"|"Ice", colour: "yellow"|"amber"|"red" (lowercase), issued: string (free text), issuedAt: string (ISO 8601)|null, validity: string, text: string, impacts: string[], extra: string }`.

```json
{ "forecast": { "currentTemp": 14, "issued": "06:00 22 October 2026",
    "days": [{ "day": "Thursday", "summary": "Showers, gales later", "icon": "Showers", "max": 16, "min": 12,
      "windDescription": "…gusts to 75 mph", "windDir": "S", "windForce": "6-8", "windMph": 35, "maxGustMph": 75, "maxRain": 80,
      "sunrise": "07:58", "sunset": "18:22", "uv": "1",
      "periods": [{ "name": "Morning", "desc": "Sunny spells", "wind": "W F6", "dir": "W", "force": "6", "mph": 28, "rain": 40, "gustMph": null }] }] },
  "warnings": [{ "type": "Wind warning", "island": "Jersey", "kind": "Wind", "colour": "amber", "issued": "Issued at 02:44 UTC Thursday 22 October 2026",
    "issuedAt": "2026-10-22T02:44:00.000Z", "validity": "From 21:00 Thu to 15:00 Fri", "text": "Severe gale F9", "impacts": ["Fallen trees"], "extra": "" }],
  "warningsChecked": "2026-10-22T06:30:00",
  "sources": { "forecast": { "ok": true }, "warnings": { "ok": true } },

```

## Unified post card (what `app.js` renders for X and Bluesky)

`mergeFeed()` adds the X posts from `x-posts.json` from the last 5 days to the `/api/feed` items, sets `source: "X", platform: "x"` on each, dedupes by `url` and sorts by `time`, newest first. An item counts as a post when `platform` is `"x"` or `"bsky"` (or `source` is `"X"` or `"Bluesky"`). Each post renders with `postCardHTML()` using:

```
{ platform: "x"|"bsky", source: "X"|"Bluesky", url: string, time: ISO 8601,
  handle: string, author?: string, avatar?: string, text: string, media?: Media[] }
```

- Header: avatar (or the initial letter), `author || handle`, `@handle`, and the platform icon.
- Body: `text` (escaped), then media.
- Footer: `HH:MM · Today|Yesterday|<date> · N min ago` and "View on X ↗" or "View on Bluesky ↗". The whole card links to `url`.
- `id` (X) and `title` (`""` on Bluesky) are not used by the card.

Any new UI should rely only on these fields and treat `author`, `avatar` and `media` as optional.

## Extending the data (modular options)

This section describes **optional** extension points. The UI (`app.js`) already reads all of them and falls back to today's behaviour when they are missing. `app.js` also has built-in defaults for every source in `BUILTIN_SOURCES`, so `sources.json` only needs the keys you want to override. Neither `sources.json` nor `config.json` exists yet. If you create one, add it to `FILES` in `tools/prepare_deploy.py` or it won't be deployed. Every field below is optional. When it is missing, the frontend must fall back to today's behaviour.

### 1. Source registry: `sources.json` (static, served at `/sources.json`)

This is one place to define how each source looks and behaves. The key is the `items[].source` / `sources[].name` value from the table above (for example `"BBC Jersey"`, `"gov.je"`, `"X"`, `"Bluesky"`).

```jsonc
{
  "version": 1,
  "sources": {
    "BBC Jersey": {
      "label": "BBC Jersey",            // display name (default: the key)
      "homepage": "https://www.bbc.co.uk/news/world/europe/jersey",
      "domain": "bbc.co.uk",            // used to derive a favicon if `favicon` is unset
      "favicon": null,                  // explicit icon URL (png/svg/ico); overrides `domain`
      "icon": null,                     // optional inline SVG or emoji, e.g. "📰"; used if no favicon
      "color": "#bb1919",               // accent colour for the badge, border or chip
      "kind": "news",                   // "news" | "official" | "warning" | "social" | "weather" | "transport" | "utility"
      "region": "jersey",               // "jersey" | "guernsey" | "channel-islands" | "uk"
      "priority": 50,                   // 0–100, higher sorts first within the same hour (default 50)
      "official": false,                // true for gov.je, Jersey Met, Ports of Jersey, etc.
      "hidden": false                   // true hides the source without code changes
    },
    "gov.je": { "domain": "gov.je", "kind": "official", "official": true, "priority": 80, "color": "#1b5e9e" }
  }
}
```

**Favicon resolution order (frontend):**
1. `favicon`, if set.
2. `https://<domain>/favicon.ico`, if `domain` is set. Load it lazily and listen for `onerror`.
3. As a fallback, a favicon service, e.g. `https://www.google.com/s2/favicons?domain=<domain>&sz=64` or `https://icons.duckduckgo.com/ip3/<domain>.ico`.
4. `icon` (emoji or SVG), or else the first letter of `label` in a coloured circle using `color`.

Always render favicons as `<img loading="lazy" referrerpolicy="no-referrer" width="16" height="16" alt="">`, so a broken icon never breaks layout. If you want the server to do this, `/api/feed` may add an optional `favicon` string to each item; the UI must still work without it.

### 2. Optional per-item display hints

Any feed item, X post or summary post may carry an optional `display` object. The refresh may set it, and the UI may ignore it.

```jsonc
"display": {
  "pinned": false,          // keep at top of its hour group
  "importance": "normal",   // "low" | "normal" | "high" | "critical" (critical = highlighted card)
  "tags": ["travel", "power"], // free-form topic tags for filters/chips
  "region": "jersey",       // overrides the source's region
  "image": null             // preferred preview image URL
}
```

### 3. Optional summary extras (`summary.json`)

- `"status"`: `"calm" | "watch" | "warning" | "severe" | "easing" | "over"`. A UI hint for a coloured status pill.
- `"highlights"`: `[{ "label": "Max gust", "value": "75 mph", "source": "https://…" }]`. Small stat chips.
- `"sections[].icon"`: an emoji or icon name for each section heading.

### 4. UI config: `config.json` (optional, static)

These are site-wide switches, so Claude Code can add features behind flags instead of hard-coding them.

```jsonc
{
  "title": "Storm Austen tracker",
  "subtitle": null,
  "theme": { "accent": "#e53935", "mode": "auto" },   // "auto" | "light" | "dark"
  "refresh": { "feedSeconds": 180, "weatherSeconds": 300, "eventsSeconds": 120 },
  "filters": { "regions": ["jersey", "channel-islands"], "showGuernseyOnlyIfImportant": true },
  "features": { "favicons": true, "postCards": true, "summaryBox": true, "statusPill": false }
}
```

### Rules for extensions

- New files (`sources.json`, `config.json`) are **owned by Jack/the UI**. The automated refresh only ever rewrites `summary.json`, `x-posts.json` and `events.json`, and may add the optional `display`, `status` and `highlights` fields to them.
- Fetch new files with a fallback: `fetch('/sources.json').then(r => r.ok ? r.json() : {}).catch(() => ({}))`.
- Never make an extension field required. Bump `version` if a shape has to change incompatibly, and keep reading the old shape.
